# AI Prompts

Усі AI-задачі в проєкті виконувались у **Claude Code** (CLI-агент від Anthropic, модель Claude Opus) прямо в
репозиторії: агент читав код, запускав тести і вносив зміни; результат перевірявся вручну.

Нижче наведено реальні промпти (оригінальною мовою), а також уточнені задачі, які з них випливали.

## 1. Інтернаціоналізація, async views, тести (ДЗ 24.1)

> проверь сначала что у меня готово потом интегрируй по этому дз все в мой проэкт не оставляй коментарии в коде но выдай мне все что ты сделал пошагово
>
> *(+ текст завдання ДЗ 24.1: i18n uk/en, ≥3 async views, ≥20 unit та ≥15 integration тестів на pytest-django, factory-boy, mock для Stripe/email, coverage ≥ 70%)*

Результат: `locale/`, 4 async views, `tests/` (factory-boy фабрики, моки Stripe і пошти), coverage 98%.
Під час написання тестів AI знайшов два баги: не був заданий `LOGIN_URL`, а `redirect(..., code=303)` насправді віддавав 302.

## 2. Code review (ДЗ — AI для покращення проєкту)

> следующее дз только адаптируй под мой проэкт *(+ текст завдання)*
>
> да выполняй

Задача для review, яку AI виконував для кожного з трьох views (`BookingCancelView`, `order_create`, `payment_success`):

```text
Зроби code review цього Django view. Шукай: проблеми безпеки (доступ до чужих даних, IDOR),
гонки (race conditions) і транзакційність, коректність грошових розрахунків, обробку помилок
зовнішніх сервісів (Stripe, SMTP), граничні випадки. Для кожної знахідки вкажи серйозність
і конкретне виправлення. Не пропонуй змін заради стилю, якщо вони не змінюють поведінку.
Перш ніж виправляти, підтверди проблему тестом.
```

Як перевірялись рекомендації: кожну знахідку або відтворювали тестом (IDOR: чужий користувач отримав 302 і
скасував бронювання), або відхиляли з поясненням. Наприклад, «обрізання копійок у `int(price * 100)`» виявилось
хибною тривогою, бо `price` має тип `Decimal`. Деталі в [AI_REVIEW.md](AI_REVIEW.md).

## 3. Генерація тестів для моделей

```text
Згенеруй pytest-django тести для моделей Booking, Order/OrderItem, Resource/ResourceCategory:
__str__, значення за замовчуванням, сортування, валідація в clean() (минуле, end <= start,
перетин бронювань, скасовані бронювання не блокують слот), get_cost/get_total_cost,
переклад verbose_name і choices. Використовуй factory-boy фабрики з tests/factories.py.
```

Перевірено і доопрацьовано вручну: додано тести на суміжні бронювання і на повторне збереження без
конфлікту з самим собою, а також тести на нову властивість `Booking.is_cancellable`. Кожен тест позначено
коментарем `# Generated with AI, reviewed and modified`.

## 4. Docstrings

```text
Напиши docstrings для всіх views у apps/*/views.py: що робить view, які HTTP-методи і параметри
приймає, права доступу, що повертає у крайніх випадках (404/400/redirect). Коротко, англійською,
без повторення коду.
```

Згенеруй README.md для цього проєкту на основі коду: опис, стек, запуск через docker compose
